or a root script works the same way; see [Generic MDM scripts](/docs/enterprise/generic-scripts).

## Windows (Win32 app)

1. **Prerequisite app: PowerShell 7.** Package Microsoft's PowerShell 7 MSI
   as its own app and add it as a dependency of the DefenseClaw app. The
   standalone lifecycle refuses to run without it (`powershell7_required`).
2. **Package.** Put `DefenseClawSetup-Enterprise-x64.exe`, `config.yaml`
   and, for unsigned builds, `payload-trust.json` in one folder and wrap it
   with `IntuneWinAppUtil.exe`.
3. **Program.**

   | Field | Value |
   | --- | --- |
   | Install command | `DefenseClawSetup-Enterprise-x64.exe /ensure CONFIG=config.yaml` |
   | Uninstall command | `DefenseClawSetup-Enterprise-x64.exe /uninstall` |
   | Install behavior | System |
   | Return codes | `0` success, `1707` success, `3010` soft reboot, `1641` hard reboot, `1618` retry |

4. **Requirements.** 64-bit Windows; the minimum OS your fleet supports.
5. **Detection rule.** Registry: key
   `HKEY_LOCAL_MACHINE\SOFTWARE\Cisco\DefenseClaw\Enterprise`, value
   `ProductVersion`, string comparison *equals* the version you deploy. The
   Add/Remove Programs entry `CiscoDefenseClawEnterprise` carries the same
   `DisplayVersion`.
6. **Supersedence.** For an upgrade, create the new version's app and have it
   supersede the old one without uninstalling; `/ensure` upgrades in place.

Intune's management extension is a 32-bit process and runs scripts in
Windows PowerShell 5.1. That is why the install command is the native Setup
executable rather than a script. For a Remediations script, have it only
launch the installed CLI (`enterprise windows verify`, then `repair`); do not
run lifecycle logic in Windows PowerShell.

## macOS

1. **Config script.** A root shell script (Devices → macOS → Shell scripts)
   that writes `/opt/cisco/defenseclaw/etc/config.yaml` and, if used, stores
   the AI Defense key with `enterprise secret set --from-stdin`. Intune's
   macOS scripts do not use a proxy; stage what the script needs.
2. **App.** Upload `defenseclaw-enterprise-<version>-darwin-arm64.pkg` as a
   macOS line-of-business (PKG) app. Its postinstall runs
   `enterprise macos ensure --from-package`.
3. **Detection.** The package receipt `com.cisco.defenseclaw.enterprise` at
   the deployed version.
4. **Optional.** A PPPC profile only if agent configuration lives in
   privacy-protected folders (see [macOS](/docs/enterprise/macos#privacy-prompts)).

## Linux

Intune's Linux support is centered on enrollment and compliance rather than
software deployment. Deploy the `.deb` or `.rpm` with your usual Linux
software channel and run the [generic script](/docs/enterprise/generic-scripts)
as root.

## Testing without a tenant

Intune cannot enroll Windows Server. Without a Windows client tenant, reproduce
Intune's execution contexts directly:

- run `DefenseClawSetup-Enterprise-x64.exe /ensure` as SYSTEM from a 32-bit
  parent process;
- run the registry detection rule;
- run the Remediations script under `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`;
- start two installs at once and expect one `1618`;
- run with no user signed in.
