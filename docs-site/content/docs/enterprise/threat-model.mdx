row per threat and the evidence for each control, live in the repository:
[`docs/ENTERPRISE-THREAT-MODEL.md`](https://github.com/cisco-ai-defense/defenseclaw/blob/main/docs/ENTERPRISE-THREAT-MODEL.md)

## Who is trusted

| Trusted | Not trusted |
| --- | --- |
| Administrators, root, LocalSystem, the MDM agent, the signer of the release | A standard user, any AI agent running as that user, a prompt that steers the agent, another local user, a compromised gateway process |

DefenseClaw does not defend a machine from its own administrator. An agent
given unrestricted sudo or administrator rights is an administrator.

## Boundaries

| Crossing | Threat | Control |
| --- | --- | --- |
| MDM → services and state | Untrusted payload or engine runs as administrator | Fixed layout; locked, snapshotted transaction with rollback; PowerShell 7 resolved only from HKLM and Microsoft-signed; Authenticode or hash-pinned payloads |
| User → services | Stop, disable or replace a service | Query-only SCM access; root-owned units and plists; indefinite restart |
| User → admin state | Edit config, policy, secrets, manifest, ledger | Administrator-only write on every file and parent; untrusted inputs rejected at load |
| Gateway → admin state | A compromised gateway widens its own policy | Read-only config, policy and ledger for the gateway identity |
| Hook → gateway | A user impersonates the gateway during a restart | No credential or payload sent before the listener is proven: SCM PID for Windows hooks; a listener proof (an HMAC only the gateway can compute from the user's credential) for the Windows OpenCode and Amp plugins; `SO_PEERCRED`/`LOCAL_PEERCRED` uid on the hook socket, which Linux and macOS hooks and plugins use exclusively (no TCP fallback); PID 1 holds Linux sockets across restarts |
| Gateway → caller | An unenrolled user uses a per-user connector, or one user's credential posts events attributed to another | Kernel uid checked against the root-owned authorization ledger on the hook socket; on TCP, per-user credentials bound to the uid or SID, accepted only while the ledger protects that user, with events attributed to that identity and conflicting identity headers refused |
| Guardian → user home | Root follows a user-planted link | Windows writes under the user's token; Linux and macOS use a worker running as the user |
| Enumerator → manifest | Directory outage revokes users; uid reuse | Only a definitive not-found revokes, after several misses; uid and home identity |
| Guardian → vendor policy | Administrator policy overwritten | DefenseClaw-owned entries only, with ownership records and preimages |
| User/project hook → agent | A hook rewrites a tool call after inspection | Vendor locks for Codex and Claude Code; the [foreign-hook guard](/docs/enterprise/foreign-hook-guard) elsewhere |
| Gateway → AI Defense | API key leaks | Protected credential only; never logged; inline keys rejected |

## Invariants

- The gateway never runs as root or LocalSystem.
- No privileged process writes a user home with its own credentials.
- A hook sends nothing to an unverified listener.
- The authorization ledger, not a status file, decides enrollment and
  readiness.
- A lookup error never revokes a user.
- DefenseClaw changes only the policy entries it owns.
- Secrets are never logged or printed.
- `Running` is not readiness; partial coverage is reported as incomplete.

## Residual risks

| Risk | Scope |
| --- | --- |
| A user can delete their own per-user hook registration until the next repair | Per-user connectors |
| Claude Code `--bare` / `CLAUDE_CODE_SIMPLE=1` skip managed prompt and session hooks; tool hooks still run | Claude Code |
| Amp has no machine plugin location and no defined plugin order | Amp |
| OpenCode's managed-plugin-last order is observed, not documented | OpenCode |
| OpenCode pure mode (`--pure`, `OPENCODE_PURE=1`) and `OPENCODE_TEST_MANAGED_CONFIG_DIR` start a session without any DefenseClaw plugin | OpenCode |
| Hermes cannot fail closed; Copilot command-hook timeouts fail open | Hermes, Copilot |
| A user holding the gateway endpoint while it is down can block hooks (they fail closed) but cannot forge an allow | All platforms |
| A user holding the gateway's TCP port while it is down receives what the agents' own telemetry exporters send, including the sending user's per-user telemetry credential, and can then post telemetry attributed to that user until the user leaves enrollment | Codex, Claude Code, Gemini CLI, OpenHands and OmniGent telemetry; every restart on macOS and Windows, Linux only while an administrator has the socket unit stopped |
| In the Secure Client profile hook and telemetry credentials are shared per connector, so one user can post events attributed to another user of the same connector | Secure Client, Windows and macOS |
| Unsigned, hash-pinned builds do not satisfy WDAC, AppLocker or Gatekeeper publisher rules | Windows, macOS |
| Cloud or MDM vendor policy can override local machine policy | Codex, Claude Code |
| A compromised privileged DefenseClaw service holds administrator-equivalent power | All platforms |
